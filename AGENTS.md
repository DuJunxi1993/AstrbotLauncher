# AGENTS.md — AstrBot Launcher

## What this is
Native macOS SwiftUI launcher (SwiftPM, macOS 26+, Swift 6.2) that manages
three external services: **AstrBot** (via `uv`), **NapCat** and **Shipyard**
(via `docker compose`).

Branch: `macos`. This repo is an umbrella — `main` and `windows-wsl` exist
for other platforms; do not push macOS-only changes elsewhere.

## Build / run

| Goal | Command |
|------|---------|
| Produce signed `AstrbotLauncher.app` | `bash build.sh` |
| Build only (no bundle) | `swift build -c release` |
| Dev run | `bash run.sh` |
| Override config | `CONFIG=debug bash build.sh` (default: release) |

- No `swift test` target, no XCTest, no SPM dependencies, no SwiftLint /
  SwiftFormat. Don't add any of these without asking.
- Bundle: `AstrbotLauncher.app` at repo root (regenerated by `build.sh`).
  Binary: `.build/<config>/AstrbotLauncher`.

## Layout (Sources/AstrbotLauncher/)

- `App/AstrbotLauncherApp.swift` — `@main`, `AppDelegate`, scene commands.
- `Models/` — `ServiceType` (.astrbot / .napcat / .shipyard),
  `AstrBotLaunchMode`, `ServiceStatus`, `Service`, `AppSettings` (singleton
  `@MainActor`, all keys in `AppSettings.Key`, persisted to
  `UserDefaults.standard`).
- `Managers/` — `AppState` (singleton `@MainActor` coordinator),
  `AstrBotController` + `AstrBotProcessManager` + `ProcessSpawner` (daemonize
  via `posix_spawn`), `ContainerController` (docker ps/inspect), `LogWatcher`
  (file tail for AstrBot, `docker logs` for containers), `PathDetector`,
  `SystemIntegration` (`SMAppService` login item, `UNUserNotificationCenter`).
- `Views/` — `MainWindow/` (NavigationSplitView + sidebar/detail),
  `Settings/`, `Components/`, `MenuBar/`.
- `Utilities/` — `ShellExecutor`, `Logger` (os.Logger, subsystem
  `com.djx.astrbotlauncher`), `LogBatcher`, `DockerComposePortParser`,
  `WebUIURLDetector`, `Theme`.

All managers are `@MainActor`. `Package.swift` enables `StrictConcurrency`
and `BareSlashRegexLiterals` — keep code actor-correct.

## Non-obvious constraints

- **No customizable toolbar.** `MainWindowView.swift` uses a plain
  `.toolbar { }` with 5 fixed items. Do **not** add `.toolbar(id:)` or
  `customizationBehavior()` — it crashes on macOS 26.5.1.
  `AstrbotLauncherApp.init()` scrubs stale `NSNavToolbarCustomization-*` /
  `NSToolbar Identifier *` UserDefaults keys; keep that cleanup.
- **AstrBot is daemonized.** `ProcessSpawner.spawnDaemon` calls
  `posix_spawn` with `POSIX_SPAWN_SETSID` only. Do **not** combine with
  `POSIX_SPAWN_SETPGROUP` — it returns `EPERM` on macOS. CWD is the
  **parent** of `settings.dataDirectory` (see `AstrBotProcessManager.start`).
  Stop is SIGTERM → 5 s → SIGKILL via `kill(2)`. Quitting the app does not
  stop AstrBot.
- **ServiceType inference** (`Models/ServiceType.swift`) is a
  case-insensitive `contains("astrbot"|"napcat"|"shipyard")` match on
  docker image or container name. New service types need a case +
  displayName / iconName / accentColor entries; keyboard shortcuts are
  also defined in `AstrbotLauncherApp.shortcutKey(for:)`.
- **Settings keys** all live in `AppSettings.Key` and persist to
  `UserDefaults.standard` — do not invent new key strings ad-hoc.
- **`.gitignore` excludes** but currently present in the working tree:
  `AstrbotLauncher.app/`, `data/`, `*.dmg`, `*.zip`,
  `release-checksums.txt`. Don't commit them.

## CI

- `.github/workflows/build-macos.yml` runs on push/PR to `macos` and tags
  `macos-v*`. It is **intentionally a placeholder** marked
  `continue-on-error: true` because the `macos-15` runner lacks the
  macOS 26 SDK (`glassEffect` / `glassProminent` APIs). When GitHub ships
  a `macos-26` runner, bump `runs-on: macos-15` → `macos-26` and remove
  the `continue-on-error`.
- Release tags use `macos-v<semver>` (e.g. `macos-v1.0.4`). On tag push
  the workflow creates a GitHub Release with the zipped bundle.

## Releases

- `RELEASE.md` is the single source of truth (per-version files were
  consolidated in commit f92f1f8). When cutting a release:
  1. Update the top "Latest Release" block — version, date, download
     table, SHA256.
  2. Prepend a new section to "Changelog" (reverse chronological).
  3. Update stable sections (主要功能 / 安装 / 首次使用 / 系统要求) only
     when something actually changed.
- Per release, bump `CFBundleShortVersionString` in
  `Resources/Info.plist`. `LSMinimumSystemVersion` is fixed at `26.0`.

## First-run notes (also in README)

- No Apple Developer signing — `build.sh` ad-hoc signs only. First launch
  triggers Gatekeeper; user must right-click the `.app` → Open in Finder,
  or run `xattr -dr com.apple.quarantine AstrbotLauncher.app`.
- Upgrades from v1.0.0/v1.0.1 require deleting the old `.app` from
  `/Applications` to clear stale toolbar-customization UserDefaults.
